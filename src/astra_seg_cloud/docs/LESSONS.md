# 经验与坑（LESSONS）

一句话总结：**几何只能来自点云与平面；2D mask 只做归属；GT 不能由被评估系统产生；任何"平滑/保持"都要有异常帧开关；每次改动都要 A/B 且可回滚。**

每条都带当时的实测数字，方便以后判断"这条还成立吗"。

---

## 一、奏效的做法（保留，别乱改）

| 做法 | 为什么有效 | 实测证据 |
|---|---|---|
| 整帧反投影 → 去桌面 → **远→近认领**，每物体 `mask_k -= 更近物体 mask` | 近物体在前，远的被遮挡关系天然确定 | keyboard/cup 均 121/121 帧 |
| **只从场景里删除 `true_pts`**（不删整个 mask） | 删整个 mask 会把被遮挡的物体一起删没 | 修复"后面物体整帧消失" |
| 圆柱**跳过平面裁剪**、`min_pts 80→35` | 曲面不贴合平面带，裁剪后只剩一条 | 杯子出现率 ↑，121/121 |
| 圆柱 yaw 用**桌面法线的规范基 + 方形 footprint（取 min 直径）** | 圆柱自身轴在抖、±n 有 180° 歧义 | yaw std **138.8° → 0.22°** |
| 桌面判定加**跨帧一致性**（法线 ≤10°、偏移 ≤3 cm） | 防止 RANSAC 锁到键盘/书顶面 | 键盘 **71/122 → 121/121** |
| **footprint = mask 四边形**（矩形正则化），高度 = 平面拟合 | 四边形把 mask 毛刺平均掉，尺寸稳定 | 尺寸 std 0.1 cm 级 |
| ORT/OpenBLAS **线程限 1 + 关自旋** | 20 核自旋占 1800% CPU | **8.7 → 15 fps** |
| RViz 用 `systemd-run --user --collect` + 干净环境 | 继承宿主会话会崩 GUI | 宿主不再崩 |
| **可解性 gate**（认领率/法向残差/平面内点比/遮挡） | 把"这帧可不可信"和"几何拟合"分开 | 误检帧被标 `quality=0` |
| **标签投票 + 冻结 + 低分归 object** | COCO 对本书只有 0.14–0.27 分 | book **7/152 → 151/151**，标签变化 0/2 |
| 显示点云**按框裁一次** | `filter_to_obb` 只对 `source='plane'` 生效，quad 分支没裁 | 点不再跑到框外 |
| 桌面 RANSAC 迭代 80→40、重试 +2→+1；四边形拟合初值好就跳过 | 最多跑 3 次 RANSAC + 每次 least_squares | 延迟 **55 → 52 ms** |
| **ArUco 加"贴在已知平面"的约束** | 平面 PnP 有镜像二义性 | 6DoF 旋转误差 **25–34° → 0.5°** |
| yaw 偏移用**相机系两轴夹角**（不是 marker 系里变换） | 基不一致会系统性偏 | 偏 **17–22° → 0.5°** |
| **yaw GT = marker yaw + 设计常数 90°** | 短边 ∥ marker 边是设计约束，不是标定 | 无自由参数、无循环论证 |
| 最小外接矩形（旋转卡壳）求 footprint | 近正方形物体 PCA 轴不稳、尺寸被对角线离群点撑大 | 23.7×19.8 vs 真值 23.4×18.5（当前管线 25.6×20.6） |

## 二、失败的坑（别再走一遍）

| 坑 | 为什么错 | 数字 / 后果 |
|---|---|---|
| 把 3D 框往 2D mask 上"凑" | 用不可信的 2D 当几何真值 | 用户明确否决（"作假"） |
| 每帧对尺寸/中心做限速 | 引入滞后，运动时更差 | 用户否决（"效果 bad"） |
| 拟合失败时保持上一帧 OBB | 看起来像漂移、掩盖失败 | 用户否决 |
| 区域生长（体素 6-邻域）当默认裁剪 | 合成测试漂亮，实测框更松 | keyboard 宽 **11.9 → 13.6 cm** |
| 类别尺寸先验（median+MAD，3σ 替换） | 把偏松的尺寸学成"正常"并锁死 | 默认关 |
| 按点云范围收紧 footprint（无条件） | 4 mm 平面裁剪已把边缘点删了，收过头 | keyboard **31.8 → 24.3 cm** |
| 调小 `obb_margin` 想收紧框 | 被 `contain_points` 重算覆盖 | 尺寸几乎不变 |
| 认领率分母用 **mask 像素数** | 深色物体大量像素无深度 | `quality` 全 0，框全灰 |
| 噪声指标用 **z 方向跨度 / 最小尺寸** | z 跨度是几何（30 cm 斜板），不是噪声 | 100% 帧被判死；改成"沿法线残差"后正常 |
| 引入 `_NamedDet` 后仍用 `type(d)(...)` 构造 | 按包装类型构造，参数不符 | `takes 3 args but 5 given`，整帧全挂 |
| 相机驱动重复启动（同话题 2 个 publisher） | 帧交错、彩色/深度可能配错 | 框跑到画面边缘、ROI 全丢 |
| 同一物体被拆成两个 track（一个出生在阈值下→永久 `object`） | 标签冻结没有"升级"路径 | 约一半帧拿不到目标标签 |
| **GT 偏移用管线输出标定** | 循环论证：管线错，GT 跟着错 | 一致性可以，绝对精度不行 |
| **GT 尺寸从管线抄** | 拿结果当真值 | 用户当场指出，必须改 |
| 从"角度变了"就断言"物体转动了" | 可能只是换了对实例/换了基 | 我误判过一次"书转了 87°"，实际没动 |
| 把 3D 线框画在 RGB 上判断框好坏 | 透视下前后棱重叠，人眼判不了 | 改成"3D 点投影浅色 mask + 细轮廓 + 细轴" |

## 三、指标口径（避免自欺）

| 要判断的事 | 该用的量 | 不该用的量 |
|---|---|---|
| 框紧不紧 | `框尺寸 vs 真值`、`框尺寸 vs 点云范围` | "框内点 100%"（弱指标） |
| 稳不稳 | 尺寸/中心/yaw 的 std、p95、长时序漂移 | 单帧截图 |
| GT 可信吗 | GT 自身抖动（marker 单帧 1–4 mm、0.4°；100 帧平均 ~0.1 mm） | 用同一套算法标定出来的偏移 |
| 改进了吗 | A/B 同场景同帧数，延迟 p50/p99 一起看 | "看起来好多了" |
| 高度 | 支撑面 → 顶面 的距离 | 点云沿法线的 max−min |

## 四、性能预算（320×240，15 fps 是相机上限）

```
单帧 ≈ 52 ms：转换 0.3 + 推理 21 + 点云 30 + 落包 1
点云内部：反投影 0.3 + 桌面 RANSAC 9 + 逐物体拟合 8.6/个
```

新增任何一步，先估 ms 再看是否值得；超过 60 ms 就要动别的预算。
